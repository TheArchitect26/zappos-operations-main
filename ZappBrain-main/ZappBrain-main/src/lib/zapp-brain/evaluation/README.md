# 📊 Zapp OS Phase 23 — Continuous Learning, Intelligence Evaluation & Rule Validation

Welcome to **Phase 23: Continuous Learning, Intelligence Evaluation & Rule Validation Framework** for Zapp Brain.

This module provides a scientific, deterministic, and explainable evaluation framework that continuously assesses how well Zapp Brain makes predictions, captures alerts, recommends actions, and reports operational outcomes against the ground truths generated by the **Fleet Digital Twin**.

---

## 🏗️ Evaluation Architecture

The framework coordinates the following components:

```
    [ Fleet Digital Twin ] ──► (Ground Truth / Expected Outcomes)
              │
              ▼
         [ Zapp Brain ] ──► (Actual Insights / Recommendations)
              │
              ▼
   [ Intelligence Evaluation Engine ] ──► (engine.ts)
              │
    ┌─────────┴─────────┐
    ▼                   ▼
[ Accuracy Metrics ] [ Rule Analytics ]
  (metrics.ts)         (rule-performance.ts)
    │                   │
    ▼                   ▼
[ Calibration ]      [ Scorecards / Leaderboards ]
  (calibration.ts)     (scorecards.ts, leaderboard.ts)
```

### 📋 Module Structure
1. **`types.ts`**: Holds unified TypeScript interfaces representing scores, metrics, calibration rules, and regression logs.
2. **`engine.ts`**: The main evaluation coordinator receiving a simulation state and brain results to produce an execution report.
3. **`metrics.ts`**: Pure math module computing accuracy, precision, recall, specificity, F1-score, and Matthews Correlation Coefficient.
4. **`rule-performance.ts`**: Manages sliding-window performance metrics of logical heuristics to ensure true alarms match user responses.
5. **`scenario-analysis.ts`**: Grades intelligence success across diverse situational loads (e.g. storms, heavy rain, holiday traffic).
6. **`drift.ts`**: Monitors quality deterioration, declining confidence rates, or sudden signal drops.
7. **`calibration.ts`**: Auto-proposes threshold changes (like adjusting GPS jitter limits or delays) pending supervisor approval.
8. **`leaderboard.ts`**: Scores lists highlighting top and bottom-performing rules and scenario challenges.
9. **`scorecards.ts`**: Category-level evaluation cards (Mechanical, Routing, Compliance) for dashboard visualization.
10. **`comparison.ts`**: Comparative laboratory evaluating Version A versus Version B metrics.
11. **`replay.ts`**: Framework facilitating play, pause, bookmarking, and step-by-step playback with mathematical reproducibility.
12. **`history.ts`**: Accumulator saving daily, weekly, and quarterly trends.
13. **`reports.ts`**: Role-specific, action-oriented briefing generators for various managers.
14. **`export.ts`**: Handles serialization formats (JSON, JSONL, CSV, TypeScript, Markdown).
15. **`tests.ts`**: Integrates fully self-contained automated diagnostic test suites.

## 📐 Accuracy Formulas & Metric Definitions

All metrics are calculated deterministically under standard binary classification models:

### 1. Accuracy
$$Accuracy = \frac{TP + TN}{TP + TN + FP + FN}$$
Measures the overall ratio of correct assessments.

### 2. Precision
$$Precision = \frac{TP}{TP + FP}$$
Calculates the purity of triggered alarms. High precision prevents operator alarm fatigue.

### 3. Recall (Sensitivity)
$$Recall = \frac{TP}{TP + FN}$$
Measures the coverage rate of captured incidents. High recall ensures no critical safety violations are missed.

### 4. Specificity
$$Specificity = \frac{TN}{TN + FP}$$
Calculates the percentage of correctly identified clean (normal) conditions.

### 5. F1-Score
$$F1 = 2 \times \frac{Precision \times Recall}{Precision + Recall}$$
The harmonic mean of Precision and Recall, representing total classification quality.

### 6. Matthews Correlation Coefficient (MCC)
$$MCC = \frac{TP \times TN - FP \times FN}{\sqrt{(TP + FP)(TP + FN)(TN + FP)(TN + FN)}}$$
The gold-standard metric for binary classifications, especially robust on highly imbalanced datasets.

## 🚦 Calibration & Regression Testing

### 🔧 Auto-Calibration Proposals
When rule performance drops, the calibrator generates targeted recommendations:
* **Reduce GPS Jitter Sensitivity**: Suggested when a rule triggers multiple false positives in short intervals.
* **Lower Operational Delay Threshold**: Suggested when critical linehaul delay alerts are missed.
* **Adjust Weighting Factor**: Suggested when a rule's average confidence output is persistently low.

### 🔄 Regression Testing
Whenever rules are optimized, the system compares the updated intelligence against the baseline.
If **Accuracy** or **F1 Score** declines by more than 5%, the regression suite blocks the update, guaranteeing zero-degradation safety during rule tuning.

## 🚀 Developer Onboarding & Usage

To integrate the evaluation suite into a new pipeline, follow this pattern:

```typescript
import { IntelligenceEvaluationEngine } from './evaluation/engine';

// 1. Initialize
const evalEngine = new IntelligenceEvaluationEngine();

// 2. Evaluate
const report = evalEngine.evaluateSimulationRun({
  simulation: simState,
  zappBrainResult: cognitiveInsights,
  expectedOutcomes: groundTruths,
  scenarioName: 'Border Congestion'
});

console.log(`F1 Index: ${report.metrics.f1Score}%`);
```
